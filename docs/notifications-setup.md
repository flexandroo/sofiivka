# Сповіщення про нові замовлення й заявки (Telegram і email)

Коли на сайті з’являється замовлення або заявка (або менеджер створює замовлення вручну), база даних
кличе функцію `crm-notify`. Функція надсилає коротке повідомлення: номер, ім’я, телефон, кількість
товарів і сума, спосіб отримання, посилання на замовлення в адмінці.

- **Telegram** — бот пише кожному chat id з налаштувань.
- **Email** — один лист через сервіс [Resend](https://resend.com) на всі адреси з налаштувань
  (той самий текст, що й у Telegram: HTML-версія й звичайний текст).

Канали незалежні: можна підключити лише Telegram, лише email або обидва. Якщо для каналу є
отримувачі, але не задано його секрети, канал пропускається, а журнал у адмінці пише чому
(наприклад «Email пропущено: не задано секрети RESEND_API_KEY і NOTIFY_EMAIL_FROM»).

Налаштування робиться один раз для кожного проєкту Supabase: спершу DEV (`wfxcklglujgramasdzyr`),
перевірка, потім PROD (`fkjarsouuchjiedrrblc`).

## 1. Міграція

Supabase → SQL Editor → вставити весь файл
`supabase/migrations/20261002001200_crm_notifications_v1.sql` → Run.
(Через MCP-конектор не застосовувати: там створення розширення й тригерів.)

## 2. Бот (для Telegram)

1. У Telegram відкрити **@BotFather** → `/newbot` → назва (наприклад «Софіївка замовлення») →
   username, що закінчується на `bot`.
2. BotFather надішле **токен** вигляду `123456789:AA...`. Нікому його не пересилати.

Якщо Telegram не потрібен, цей крок і крок 6 пропустіть.

## 3. Resend (для email)

1. Зареєструватися на <https://resend.com> (безкоштовний тариф: до 3 000 листів на місяць,
   100 на день — для сповіщень магазину достатньо).
2. **Відправник.** Є два варіанти:
   - **Свій домен (для роботи).** Resend → **Domains** → **Add Domain** → вписати домен сайту
     (або піддомен, наприклад `mail.ваш-домен.ua`). Resend покаже DNS-записи (TXT для SPF і DKIM,
     MX). Додати їх у панелі реєстратора домену й дочекатися статусу **Verified** (від кількох
     хвилин до доби). Відправник тоді: `Софіївка <orders@ваш-домен.ua>` (адреса може не існувати
     як скринька, головне — домен підтверджений).
   - **Без домену (лише для перевірки).** Відправник `Софіївка <onboarding@resend.dev>`. Такі листи
     Resend доставляє **тільки на email, з яким зареєстровано акаунт Resend**. Для інших
     отримувачів буде помилка «You can only send testing emails to your own email address».
3. Resend → **API Keys** → **Create API Key** → права **Sending access** (за бажанням — лише для
   свого домену) → скопіювати ключ вигляду `re_...`. Його показують один раз.

## 4. Секрети функції

Придумати довгий випадковий рядок для `CRM_NOTIFY_SECRET` (32+ символи, латиниця й цифри; наприклад
результат `openssl rand -hex 24`).

Supabase → Edge Functions → Secrets → додати:

| Назва | Значення |
| --- | --- |
| `CRM_NOTIFY_SECRET` | рядок, який ви придумали (обов’язково) |
| `TELEGRAM_BOT_TOKEN` | токен від BotFather (для Telegram) |
| `RESEND_API_KEY` | ключ `re_...` з Resend (для email) |
| `NOTIFY_EMAIL_FROM` | відправник, наприклад `Софіївка <orders@ваш-домен.ua>` або `Софіївка <onboarding@resend.dev>` (для email) |
| `ADMIN_BASE_URL` | необов’язково; за замовчуванням `https://sofievka.vercel.app` |

Email надсилається лише тоді, коли задано **обидва** секрети `RESEND_API_KEY` і `NOTIFY_EMAIL_FROM`.

## 5. Розгортання функції

На комп’ютері, де підключено Supabase CLI, у папці проєкту:

```bash
npx supabase functions deploy crm-notify --project-ref <ref проєкту> --no-verify-jwt
```

`--no-verify-jwt` обов’язковий: функцію кличе база даних, а не користувач. Захист — заголовок із
`CRM_NOTIFY_SECRET`. Після зміни коду функції (наприклад, коли додано email) її треба розгорнути
ще раз; зміна лише секретів нового розгортання не потребує.

## 6. Адреса функції й секрет у базі

Supabase → SQL Editor:

```sql
update public.crm_notify_config
set function_url = 'https://<ref проєкту>.supabase.co/functions/v1/crm-notify',
    secret = '<той самий CRM_NOTIFY_SECRET>',
    updated_at = now()
where id = 1;
```

Таблиця закрита для сайту й адмінки; секрет ніде не показується.

## 7. Chat id отримувачів (Telegram)

Бот може писати лише тим, хто сам почав з ним розмову.

- **Особисто:** кожен отримувач відкриває бота й натискає **Start** (`/start`).
- **Група:** додати бота в групу й написати там будь-яке повідомлення.

Потім відкрити в браузері `https://api.telegram.org/bot<ТОКЕН>/getUpdates` і знайти
`"chat":{"id": ...}`. Для людини це додатне число, для групи — від’ємне (часто починається з `-100`).

## 8. Адмінка

`/admin/settings` → «Сповіщення»: вписати email і/або chat id (кожен з нового рядка), відмітити,
про що повідомляти, → «Зберегти». Блок покаже «Підключено», якщо кроки 1, 5 і 6 зроблено. Натиснути
«Надіслати тестове повідомлення» й за кілька секунд перевірити журнал під кнопкою та пошту
(лист може потрапити в «Спам», поки домен новий — позначте його «Не спам»).

## Що означає журнал

| Стан | Пояснення |
| --- | --- |
| Надіслано | Повідомлення доставлено хоча б в один канал. Якщо якийсь канал не спрацював або пропущений, це написано в колонці «Пояснення». |
| У черзі | Запит відправлено, функція ще не відповіла. Якщо так і лишається — перевірте адресу функції. |
| Пропущено | Сповіщення вимкнено, немає отримувачів або відправку не налаштовано. |
| Помилка | Жоден канал не доставив. Причина в колонці «Пояснення». |

Часті помилки:

- **HTTP 401** — функцію розгорнуто без `--no-verify-jwt`.
- **HTTP 403** — `CRM_NOTIFY_SECRET` у секретах і в `crm_notify_config` різні.
- **HTTP 404** — функцію не розгорнуто або адреса з помилкою.
- **chat not found / bot was blocked** — отримувач не натиснув Start або заблокував бота.
- **Telegram пропущено: не задано секрет TELEGRAM_BOT_TOKEN** — додайте секрет (крок 4) і перевірте ще раз.
- **Email пропущено: не задано секрети RESEND_API_KEY і NOTIFY_EMAIL_FROM** — додайте обидва секрети (крок 4).
- **Email: The … domain is not verified** — домен відправника ще не підтверджений у Resend (крок 3)
  або в `NOTIFY_EMAIL_FROM` інший домен.
- **Email: You can only send testing emails to your own email address** — відправник
  `onboarding@resend.dev` пише лише на адресу акаунта Resend; підтвердьте свій домен.
- **Email: API key is invalid** — ключ скопійовано не повністю або його видалено в Resend.

Замовлення зберігається завжди, навіть якщо сповіщення не вдалося.
