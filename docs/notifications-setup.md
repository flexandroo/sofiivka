# Сповіщення про нові замовлення й заявки (Telegram)

Коли на сайті з’являється замовлення або заявка (або менеджер створює замовлення вручну), база даних
кличе функцію `crm-notify`, і бот надсилає коротке повідомлення в Telegram: номер, ім’я, телефон,
кількість товарів і сума, спосіб отримання, посилання на замовлення в адмінці.

Email-сповіщення поки **не надсилаються**: для цього потрібен окремий поштовий сервіс. Адреси в
налаштуваннях зберігаються на майбутнє.

Налаштування робиться один раз для кожного проєкту Supabase: спершу DEV (`wfxcklglujgramasdzyr`),
перевірка, потім PROD (`fkjarsouuchjiedrrblc`).

## 1. Міграція

Supabase → SQL Editor → вставити весь файл
`supabase/migrations/20261002001200_crm_notifications_v1.sql` → Run.
(Через MCP-конектор не застосовувати: там створення розширення й тригерів.)

## 2. Бот

1. У Telegram відкрити **@BotFather** → `/newbot` → назва (наприклад «Софіївка замовлення») →
   username, що закінчується на `bot`.
2. BotFather надішле **токен** вигляду `123456789:AA...`. Нікому його не пересилати.

## 3. Секрети функції

Придумати довгий випадковий рядок для `CRM_NOTIFY_SECRET` (32+ символи, латиниця й цифри; наприклад
результат `openssl rand -hex 24`).

Supabase → Edge Functions → Secrets → додати:

| Назва | Значення |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | токен від BotFather |
| `CRM_NOTIFY_SECRET` | рядок, який ви придумали |
| `ADMIN_BASE_URL` | необов’язково; за замовчуванням `https://sofievka.vercel.app` |

## 4. Розгортання функції

На комп’ютері, де підключено Supabase CLI, у папці проєкту:

```bash
npx supabase functions deploy crm-notify --project-ref <ref проєкту> --no-verify-jwt
```

`--no-verify-jwt` обов’язковий: функцію кличе база даних, а не користувач. Захист — заголовок із
`CRM_NOTIFY_SECRET`.

## 5. Адреса функції й секрет у базі

Supabase → SQL Editor:

```sql
update public.crm_notify_config
set function_url = 'https://<ref проєкту>.supabase.co/functions/v1/crm-notify',
    secret = '<той самий CRM_NOTIFY_SECRET>',
    updated_at = now()
where id = 1;
```

Таблиця закрита для сайту й адмінки; секрет ніде не показується.

## 6. Chat id отримувачів

Бот може писати лише тим, хто сам почав з ним розмову.

- **Особисто:** кожен отримувач відкриває бота й натискає **Start** (`/start`).
- **Група:** додати бота в групу й написати там будь-яке повідомлення.

Потім відкрити в браузері `https://api.telegram.org/bot<ТОКЕН>/getUpdates` і знайти
`"chat":{"id": ...}`. Для людини це додатне число, для групи — від’ємне (часто починається з `-100`).

## 7. Адмінка

`/admin/settings` → «Сповіщення»: вписати chat id (кожен з нового рядка), відмітити, про що
повідомляти, → «Зберегти». Блок покаже «Підключено», якщо кроки 1, 4 і 5 зроблено. Натиснути
«Надіслати тестове повідомлення» й за кілька секунд перевірити журнал під кнопкою.

## Що означає журнал

| Стан | Пояснення |
| --- | --- |
| Надіслано | Повідомлення доставлено хоча б одному отримувачу. |
| У черзі | Запит відправлено, функція ще не відповіла. Якщо так і лишається — перевірте адресу функції. |
| Пропущено | Сповіщення вимкнено, немає отримувачів або відправку не налаштовано. |
| Помилка | Причина в колонці «Пояснення». |

Часті помилки:

- **HTTP 401** — функцію розгорнуто без `--no-verify-jwt`.
- **HTTP 403** — `CRM_NOTIFY_SECRET` у секретах і в `crm_notify_config` різні.
- **HTTP 404** — функцію не розгорнуто або адреса з помилкою.
- **chat not found / bot was blocked** — отримувач не натиснув Start або заблокував бота.
- **Не задано секрет TELEGRAM_BOT_TOKEN** — додайте секрет (крок 3) і перевірте ще раз.

Замовлення зберігається завжди, навіть якщо сповіщення не вдалося.
