# SEO-аналітика та інтеграції ТД «Софіївка»

## Google Tag Manager та GA4

У `/admin/settings` у розділі «Інтеграції» задайте контейнер GTM цього сайту. Для прямого підключення GA4 можна вказати ідентифікатор `G-…`. Якщо налаштовані обидва поля, сайт використовує GTM. Налаштування cookie визначають, коли відвідувач дозволяє завантажити теги й зберегти атрибуцію. Після дозволу скрипти запускаються після готовності документа, під час взаємодії або простою браузера зі стелею 2,5 с.

У GTM створіть Google Tag з тригером All Pages і п’ять тегів GA4 Event за таблицею. Для цих тегів увімкніть Send Ecommerce data з джерелом Data Layer. Додайте окремий Custom Event для `form_submit` з параметром `form_type`. Перевірте, чи не дублюється подія з автоматичним відстеженням форм у GA4.

| Подія | Коли надходить | Дані |
| --- | --- | --- |
| `view_item` | Відкрито картку товару | `currency`, `value`, `items` |
| `add_to_cart` | Збільшено кількість товару в кошику | `currency`, `value`, `items`, зміна кількості |
| `remove_from_cart` | Зменшено кількість або видалено товар | `currency`, `value`, `items`, зміна кількості |
| `begin_checkout` | Відкрито оформлення з товарами | `currency`, `value`, `items` |
| `purchase` | Сервер підтвердив замовлення з відомою сумою | `transaction_id`, `currency`, серверний `value`, `items` |
| `form_submit` | Сервер прийняв заявку | `form_type` (`contact`, `callback`, `partner_spec`) |

Усі ідентифікатори `item_id` збігаються зі стабільним каталожним ID, який фід передає як `g:id`. Перевірте потік через GTM Preview та GA4 DebugView, а потім опублікуйте налаштований контейнер. Подію `purchase` позначте ключовою, якщо цього потребує звітність.

## Атрибуція заявок і замовлень

Сайт зберігає перший перехід з UTM на 30 днів, якщо поточні налаштування cookie це дозволяють. У CRM мітки доступні в картках і CSV-експорті. Міграція `20261127152933_crm_campaign_attribution.sql` додає зберігання атрибуції в Supabase. Оновлена функція `crm-notify` додає ці мітки до наявних повідомлень менеджерам.

## Google Merchant Center

Додайте URL `/google-merchant.xml` як джерело даних для України українською мовою у верифікованому акаунті Merchant Center. Оберіть щоденне завантаження. XML бере пропозиції з поточного публічного каталогу, використовує канонічні адреси та фактичні UAH-ціни з урахуванням акцій і продажу за метр. До фіду входять опубліковані позиції з відомою ціною, підтвердженим статусом наявності, фото й коректною адресою. Для `gtin`, `mpn` і категорій Google потрібні перевірені поля каталогу та класифікація.

Завдання `Live site check` перевіряє XML, унікальність ідентифікаторів та збіг ціни й канонічної адреси вибіркових позицій. У Merchant Center перевірте результат першого імпорту, помилки облікового запису та відповідність налаштувань доставки й повернень.

## Google Search Console

У Search Console відкрийте ресурс домену. Для нового ресурсу додайте наданий Google TXT-запис у DNS. Для ресурсу з префіксом URL можна застосувати HTML-верифікацію через `GOOGLE_SITE_VERIFICATION` під час збірки. Після верифікації надішліть `/sitemap.xml` і перевірте головну, каталог та ключові сторінки товарів через інспектор URL.

Для Google Customer Reviews потрібні відповідний акаунт Merchant Center і підтверджена дата доставки, а для Binotel — ідентифікатори акаунта й дані інтеграції. Перевіряйте ці підключення у відповідних кабінетах після налаштування.
