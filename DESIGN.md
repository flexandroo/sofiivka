## Контрастні правила

- Primary CTA: `#FFC808` background + `#202020` text/icon — контраст **10.49:1**.
- Білий текст на `#FFC808` заборонений — контраст лише **1.55:1**.
- Dark surface: `#202020` background + `#FFFFFF` text — контраст **16.29:1**.
- Знижки не позначаються жовтим: для них використовується `#B42318`.

## Розподіл кольору

- 65–70% — `canvas`.
- 20–25% — `surface`.
- 8–10% — graphite surfaces і typography.
- До 5% — brand yellow.

Жовтий веде до дії, а не використовується як великий декоративний фон. На одному компоненті — один акцент.

## Typography

**Основний шрифт:** Manrope.

| Weight | Використання |
|---:|---|
| 400 | Основний текст, descriptions |
| 500 | Controls, labels, metadata |
| 600 | Product names, subheadings, navigation |
| 700 | H1–H3, prices, primary emphasis |
| 800 | Лише великі editorial/display акценти |

- Body: 16–18 px, line-height 1.5–1.6.
- Product title: 15–17 px / 600.
- PLP H1: 36–44 px / 700.
- Display: 48–64 px desktop, 34–42 px mobile.
- Ціни, коди й таблиці використовують tabular numerals.
- Uppercase не застосовується до назв товарів і довгих заголовків.
- Manrope self-host у WOFF2; `font-display: swap`.

## CTA hierarchy

1. Primary: жовтий фон, графітовий текст.
2. Secondary: графітовий фон, білий текст.
3. Tertiary: текстове посилання графітом; жовтий лише як маленький icon/underline accent.

## Surface direction

- Dark hero/header допускається на `#151515` або `#202020`.
- Каталог і PDP переважно світлі: `canvas` + `surface`.
- Product cards без жовтих рамок; yellow застосовується у CTA або selected state.
- Тіні — тільки для overlays/sticky elevation; основна структура створюється spacing і тональним контрастом.

## Homepage — затверджені продуктові обмеження

- Hero реалізується як **банерний слайдер**.
- На головній і в основних ecommerce-сценаріях **не використовуються опитування, квізи, покрокові підбори або guided selectors**.
- Основний маршрут: banner → categories → products → static solution directions → brands/services → PRO.
- Комплексні рішення можуть бути представлені лише як статичні landing cards або готові комплекти без анкетування користувача.
- Видимий порядок секцій: Header → Hero → Trust strip → Категорії → Популярні товари → Схеми → Бренди → Монтаж і сервіс → B2B / PRO → Контакти → Footer.
- `Приклади комплектації` та `Корисно знати` не показуються на головній, доки немає реальних кейсів і редакційного контенту.
- Demo-товари мають бути явно позначені та використовувати production-ready структуру `brand / model / code / specs[] / price / oldPrice / availability / image`.
- Product cutouts розміщуються на однаковій нейтральній поверхні через `object-fit: contain`; обрізання обладнання заборонене.

### Slider rules

- 2–4 слайди; рекомендовано 3.
- Один слайд — одне повідомлення, один primary CTA, за потреби один secondary link.
- Заголовки та CTA є HTML-текстом, а не частиною raster-зображення.
- Однакова висота всіх слайдів, щоб уникнути layout shift.
- Autoplay 6–8 секунд; pause on hover/focus; ручні стрілки, progress/dots, keyboard і swipe.
- На mobile використовується окремий art direction/crop, а не стиснутий desktop-банер.
- Переходи анімують тільки `transform` і `opacity`; враховується `prefers-reduced-motion`.
- Візуальний стиль слайдів узгоджений: graphite/warm surfaces, Manrope, yellow CTA; заборонена випадкова палітра кожної акції.

### Brand directory rules

- Головна сторінка відповідає лише за brand recognition: 10 featured-брендів у повільній безшовній однорядковій стрічці та CTA на окремий directory.
- Стрічка не змінює порядок брендів, призупиняється при hover/focus і перетворюється на звичайний горизонтальний список при `prefers-reduced-motion`.
- Окрема сторінка брендів відповідає за discovery: 33 catalog brands, компактні описи, алфавітна навігація та клієнтський пошук.
- На сторінці брендів немає дублюючого блоку «Популярні бренди»: після вступу починається єдиний розділ «Усі бренди».
- Westen, Viessmann і SWAG зберігаються в даних як `type: "service"`, але не показуються в єдиному каталозі «Усі бренди», доки їхній актуальний асортимент не підтверджено.
- Усі компоненти отримують дані з `brands-data.js`; майбутній маршрут зберігається лише як `futurePath` / `data-future-href` до появи реальних brand landing pages.
- Офіційний локальний логотип використовується лише за надійного джерела; інакше показується нейтральний текстовий fallback без імітації фірмового знака.
- Зовнішня поверхня всіх карток однакова. Темна внутрішня підкладка допустима лише для офіційних світлих версій логотипів.

## Engineering SVG language

- Малі піктограми: `24 × 24`, `currentColor`, графітова геометрія зі stroke `1.5`, `square` cap і `miter` join, однаковою оптичною вагою та контрольованим negative space; без градієнтів, тіней та декоративної анімації.
- Візуальна мова піктограм — технічна й архітектурна: ортогональні лінії, модульні корпуси, фланці, панелі та невеликі solid-акценти. Generic outline-паки, мультяшні метафори й надмірне заокруглення не використовуються.
- Піктограми застосовуються лише там, де пояснюють категорію або перевагу: categories і trust. Послідовність монтажу та сервісу позначається стриманою нумерацією без декоративних SVG.
- У секції комплектацій головним візуальним елементом є реальна фотографія обладнання або змонтованої системи; схематичні SVG там не використовуються.
- Для технічних міток дозволено `--info: #275D8C`. Це не другий brand color.
- Hero має один дуже делікатний generic system overlay; B2B — один background-мотив специфікації. Інші декоративні технічні патерни не додаються.
- Products і Brands лишаються чистими: engineering SVG не потрапляють у товарні фото або logo cells.

## Phase 1 refinement — production direction

- Public homepage не містить слів `demo`, `prototype` або пояснень про незавершену функціональність.
- Критичний контент видимий без JavaScript; reveal-анімація є лише progressive enhancement.
- Homepage brands — статична стіна з 10 логотипів без marquee, градієнтів і декоративної анімації.
- Mobile homepage використовує 2×2 category grid, горизонтальний список товарів, одну featured-фотографію в solutions, горизонтальні service steps і footer-accordion.
- Непідтверджені телефони, адреса та графік не показуються на homepage до отримання реальних контактних даних.
